ImageWatcher 0.7.0 사용설명서
================================

1. 프로그램 소개
----------------
ImageWatcher는 Windows 화면에서 reference.png와 같은 이미지를 실시간으로 찾습니다.
GUI 또는 CMD에서 실행할 수 있으며 이미지가 발견되면 상태를 표시하고,
설정에 따라 소리, Windows 알림,
스크린샷과 이벤트 로그를 남깁니다.


2. 빠른 시작
------------
1) 찾으려는 화면 부분을 캡처합니다.
2) 이미지 이름을 reference.png로 변경합니다.
3) reference.png를 ImageWatcher.exe와 같은 폴더에 둡니다.
4) GUI는 start_gui.cmd, CMD는 start.cmd를 더블클릭합니다.
5) GUI는 감시 종료 버튼, CMD는 Ctrl+C로 종료합니다.

기준 이미지는 글자, 아이콘, 테두리처럼 형태와 명암 차이가 있어야 합니다.
완전한 단색 이미지는 사용할 수 없습니다.


3. 배포 폴더의 필수 파일
-----------------------
ImageWatcherGUI.exe    GUI 실행 프로그램
ImageWatcher.exe       CMD 실행 프로그램
start_gui.cmd          GUI 더블클릭 실행 파일
start.cmd              CMD 더블클릭 실행 파일
settings.ini           감시 설정
reference.png          사용자가 준비하는 기준 이미지(Git 제외)
사용설명서.txt          이 문서

logs 폴더와 captures 폴더는 실행할 때 자동으로 준비됩니다.


4. 기본 실행 방법
----------------
start_gui.cmd를 더블클릭하면 설정 화면이 열립니다.
기준 이미지와 모니터를 선택하고 설정 검사 후 감시 시작을 누릅니다.
감시 중에는 설정 입력이 잠기며 일시정지·재개·종료할 수 있습니다.
한 번 테스트는 최고 점수 위치를 표시한 captures\test_preview.png를 저장합니다.

start.cmd를 더블클릭하면 기존 CMD 방식으로 실시간 감시가 시작됩니다.

정상 출력 예시:

  실시간 감시를 시작했습니다.
  종료하려면 Ctrl+C를 누르세요.

  [14:21:08] 이미지 발견 | 유사도 점수 92.10% | 위치 100,200 (80x40)
  [14:21:08] 캡처 저장 | ...\captures\detected_....png
  [14:21:11] 이미지 사라짐


5. 설정 파일
------------
settings.ini를 메모장으로 열어 수정합니다.

[watch]
reference = reference.png
monitor = 1
region = full
confidence = 0.85
disappearance_confidence = 0.80
interval_ms = 100
consecutive_matches = 2
consecutive_misses = 3
cooldown_seconds = 3

[notification]
sound = true
desktop_notification = true
save_capture = true

[storage]
log_directory = logs
capture_directory = captures
retention_days = 7
max_capture_mb = 512
max_log_mb = 5
log_backups = 3

주요 설정 설명:

reference
  기준 이미지 파일 경로입니다.

monitor
  감시할 모니터 번호입니다. 기본값은 1입니다.

region
  full이면 선택한 모니터 전체를 검사합니다.
  일부 영역은 left,top,width,height 형식으로 입력합니다.
  예: region = 100,200,800,600
  좌표는 선택한 모니터의 왼쪽 위를 0,0으로 사용합니다.

confidence
  최소 유사도 점수입니다. 0.85는 85% 이상 일치할 때 발견한다는 뜻입니다.
  값을 높이면 판정이 엄격해지고 낮추면 더 쉽게 발견하지만 오탐이 늘 수 있습니다.

interval_ms
  검사 간격입니다. 100은 약 0.1초마다 한 번 검사한다는 뜻입니다.

consecutive_matches
  발견을 확정하는 데 필요한 연속 프레임 수입니다.

consecutive_misses
  사라짐을 확정하는 연속 프레임 수입니다. 기본 3회입니다.

disappearance_confidence
  발견 이후 이 점수 미만일 때 사라짐 후보로 판정합니다. 기본 0.80입니다.
  confidence 이하로 설정해야 합니다.

cooldown_seconds
  같은 대상이 빠르게 다시 나타날 때 알림을 반복하지 않는 시간입니다.

sound / desktop_notification / save_capture
  true면 기능을 사용하고 false면 사용하지 않습니다.

retention_days
  프로그램 생성 형식 detected_YYYYMMDD_HHMMSS_ffffff.png의 캡처를
  시작 시, 매시간, 발견 이벤트 저장 후 정리합니다. 0이면 기간 제한을 끕니다.

max_capture_mb
  생성 캡처의 총용량 제한(MiB)입니다. 기본 512이며 오래된 파일부터 삭제합니다.
  0이면 용량 제한을 끕니다. 기간 제한과 독립적으로 적용됩니다.

max_log_mb / log_backups
  로그 파일당 용량(MiB)과 백업 개수입니다. 기본 5MiB, 백업 3개입니다.
  events.jsonl.1이 가장 최근 백업입니다. 로그는 기간 대신 용량으로 순환합니다.


6. 검사와 진단 명령
------------------
프로젝트 폴더에서 CMD를 열고 다음 명령을 사용할 수 있습니다.

  ImageWatcher.exe --help
  ImageWatcher.exe --version
  ImageWatcher.exe --list-monitors
  ImageWatcher.exe --check-config
  ImageWatcher.exe --test

--list-monitors
  사용할 수 있는 모니터 번호와 해상도를 표시합니다.

--check-config
  이미지 디코딩, 단색 여부, 모니터·감시 영역·이미지 크기,
  로그·캡처 폴더 쓰기 권한과 한 번의 화면 캡처·비교를 확인합니다.

--test
  화면을 한 번 검사하고 최고 유사도 점수과 위치를 표시합니다.
  발견 시 종료 코드 0, 미발견 시 1을 반환합니다.


7. 기록 위치
------------
logs\events.jsonl
  발견·사라짐 시각, 유사도 점수, 위치와 캡처 경로를 한 줄씩 기록합니다.

captures\detected_*.png
  이미지가 발견된 순간의 감시 화면입니다.

스크린샷에는 개인정보가 포함될 수 있습니다.
저장이 필요하지 않으면 settings.ini에서 save_capture = false로 변경하십시오.


8. 자주 발생하는 문제
---------------------
[설정 오류] 기준 이미지를 찾을 수 없습니다.
  reference.png가 실행 폴더에 있는지 확인합니다.

기준 이미지에 구분 가능한 무늬나 명암 차이가 없습니다.
  더 넓고 특징적인 범위를 다시 캡처합니다.

기준 이미지가 감시 영역보다 큽니다.
  더 작은 기준 이미지를 사용하거나 region을 넓힙니다.

화면에 이미지가 있지만 미발견됩니다.
  --test로 최고 유사도 점수을 확인합니다.
  confidence를 0.85에서 0.80 또는 0.75로 조금씩 낮춥니다.
  Windows 화면 배율과 기준 이미지 캡처 배율이 같은지 확인합니다.

Windows graphics function failed: BitBlt
  화면이 잠기지 않은 일반 Windows 사용자 세션에서 실행합니다.
  연결이 끊어진 원격 데스크톱이나 Windows 서비스에서는 실패할 수 있습니다.

Windows 알림이 표시되지 않습니다.
  Windows 알림 설정에서 방해 금지와 ImageWatcher 알림 허용 여부를 확인합니다.
  화면 감시와 로그 저장은 알림 실패와 별도로 계속 동작합니다.


9. 개발자용 빌드
----------------
가장 쉬운 방법:
1) 전체 소스 ZIP의 압축을 풉니다.
2) 압축을 푼 프로젝트 폴더 안의 build.cmd를 더블클릭합니다.

build.cmd는 자신의 폴더로 자동 이동합니다. 프로젝트 안에 .venv가 없으면 생성하고,
필요한 개발 패키지가 없으면 requirements-dev.txt에서 자동 설치한 뒤 빌드합니다.

CMD에서 수동으로 실행할 경우 먼저 프로젝트 폴더로 이동해야 합니다.

  cd /d "압축을 푼 ScreanCapture_solo 폴더"
  py -3 -m venv .venv
  .venv\Scripts\python.exe -m pip install -r requirements-dev.txt
  build.cmd

ERROR: Could not open requirements file 오류는 현재 CMD 위치에
requirements-dev.txt가 없다는 뜻입니다. 위 cd 명령으로 프로젝트 폴더로 이동하거나
프로젝트 폴더 안의 build.cmd를 더블클릭하면 해결됩니다.

빌드 성공 시 프로젝트 최상위 폴더에 ImageWatcher.exe와
ImageWatcherGUI.exe가 생성됩니다. 두 실행 파일은 Git에 포함되지 않습니다.


10. 지원 환경
-------------
운영체제: Windows 10 또는 Windows 11
실행 위치: 로그인된 일반 데스크톱 사용자 세션
지원 이미지: OpenCV가 읽을 수 있는 PNG/JPG 계열 이미지


11. 0.6.0 추가 기능과 동작
-------------------------
감지 점수는 OpenCV 템플릿 유사도이며 정답 확률이 아닙니다.

검사 결과 이미지 저장:
  ImageWatcher.exe --test --test-output check.png
  최고 점수 위치를 발견 시 초록색, 미발견 시 빨간색으로 표시합니다.
  감시 영역 전체를 저장하므로 필요한 경우에만 사용하세요. 기존 경로는 덮어씁니다.

저장·알림은 별도 스레드에서 순서대로 처리합니다. 대기 큐는 4개입니다.
큐가 가득 차면 해당 이벤트의 저장·알림을 생략하고 경고합니다.
종료 시 최대 5초간 대기하며 초과하면 미완료 작업 경고를 표시합니다.
캡처 오류는 1초, 2초 후 재시도하며 연속 3회 실패 시 종료 코드 3으로 종료합니다.
오류는 로그에 capture_error 이벤트로 기록합니다(큐 포화·저장 실패 시 기록 불가).
관측 실패는 발견·사라짐의 연속 횟수를 초기화하며 확정 상태는 유지합니다.
매 60초마다 실제 검사 횟수/초와 평균 처리 시간을 출력합니다.
기존 설정에 새로운 판정 항목이 없으면 기존 confidence와 consecutive_matches를 사용합니다.

개발 검증:
  .venv\Scripts\python.exe -m unittest discover -s tests -v
GitHub Actions는 Windows Python 3.12/3.13에서 테스트하고 3.12에서 EXE를 빌드합니다.
실제 화면 배율·테마별 정확도 및 Windows 알림 표시는 대상 PC에서 확인해야 합니다.


12. 0.7.0 GUI 기능과 동작
-------------------------
CMD와 GUI는 같은 WatchEngine 감지 엔진을 사용합니다.
GUI는 별도 스레드에서 감지하며 화면에는 최신 유사도 점수만 최대 초당 4회 전달합니다.
실시간 화면 영상은 표시하지 않아 캡처·OpenCV 비교 속도에 주는 부담을 줄였습니다.
최근 이벤트는 최대 200개만 화면에 유지합니다. 전체 기록은 events.jsonl에 남습니다.

GUI에서 제공하는 기능:
  기준 이미지와 모니터 선택
  전체 화면 또는 left,top,width,height 감시 영역 설정
  발견·사라짐 기준과 연속 확인 횟수 설정
  알림과 캡처 저장 설정
  설정 저장·검사, 한 번 테스트
  감시 시작·일시정지·재개·종료
  최신 점수·위치·처리 성능과 최근 이벤트 표시

감시 시작 전 이미지, 모니터, 감시 영역과 저장 폴더를 실제로 검사합니다.
감시 중에는 설정 변경을 막으며 변경 사항이 저장되지 않았으면 종료 전에 묻습니다.
GUI를 닫을 때 실행 중인 감시와 저장 작업을 먼저 종료합니다.

개발 성능 비교:
  .venv\Scripts\python.exe benchmarks\benchmark_detection.py
